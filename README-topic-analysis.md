## 核心流程概述

根据 `entrypoint.sh` 的逻辑，整个流程可以分为以下几个阶段：

1. **启动检查阶段** - 验证配置文件是否存在
2. **运行模式选择** - 根据 `RUN_MODE` 环境变量决定执行方式
3. **主程序执行** - 运行 TrendRadar 采集热点数据
4. **话题分析** - 调用 Cursor Cloud Agent 进行深度分析

## 详细说明

### 1. 启动检查阶段

容器启动时，`entrypoint.sh` 首先执行以下检查：

```bash
# 检查配置文件
if [ ! -f "/app/config/config.yaml" ] || [ ! -f "/app/config/frequency_words.txt" ]; then
    echo "❌ 配置文件缺失"
    exit 1
fi

# 保存环境变量
env >> /etc/environment
```

**必需的配置文件：**
- `config/config.yaml` - 主配置文件
- `config/frequency_words.txt` - 词频分析配置

### 2. 运行模式选择

通过 `RUN_MODE` 环境变量控制运行方式：

| 模式 | 说明 |
|-----|------|
| `once` | 单次执行后退出 |
| `cron` | 定时执行（默认模式） |
| 其他 | 直接执行传入的命令 |

### 3. 主程序执行

`run_trendradar_with_hook()` 函数包含三个步骤：

```bash
run_trendradar_with_hook() {
    /usr/local/bin/python -m trendradar    # 1. 执行热点采集
    git_auto_push                           # 2. Git 自动推送
    schedule_topic_analysis                 # 3. 调度话题分析
}
```

#### Git 自动推送 (`git_auto_push`)

当 `GIT_AUTO_PUSH=true` 时启用，功能包括：

- 检查 `.git` 目录是否存在
- 配置 Git 用户信息（通过环境变量）
- 配置 SSH 密钥（支持 `id_rsa` 和 `id_ed25519`）
- 仅提交 `output/` 目录的更改
- 自动推送到远端仓库

### 4. 话题分析

话题分析通过 `tools/run_topic_analysis.sh` 脚本实现，使用 Cursor Cloud Agent API：

#### 工作流程

1. **创建 Agent**
   ```bash
   POST https://api.cursor.com/v0/agents
   ```
   - 指定源仓库和分支
   - 发送分析 Prompt (`/collect_tech_topic`)

2. **轮询状态**
   ```bash
   GET https://api.cursor.com/v0/agents/{id}
   ```
   - 每 10 秒检查一次
   - 最长等待 1 小时（360 次检查）

3. **状态处理**
   - `RUNNING` - 继续等待
   - `FINISHED` - 分析完成，输出结果
   - `FAILED/ERROR` - 分析失败，输出错误
   - `STOPPED` - 分析被停止

4. **清理 Agent**
   ```bash
   DELETE https://api.cursor.com/v0/agents/{id}
   ```

#### 配置要求

话题分析需要配置 `CURSOR_KEY` 环境变量：

```bash
export CURSOR_KEY="your_cursor_api_key"
```

## 环境变量配置

### 基础配置

| 环境变量 | 默认值 | 说明 |
|---------|-------|------|
| `RUN_MODE` | `cron` | 运行模式：`once` / `cron` |
| `CRON_SCHEDULE` | `*/30 * * * *` | 定时执行周期（cron 表达式） |
| `IMMEDIATE_RUN` | `false` | 启动时是否立即执行一次 |
| `ENABLE_WEBSERVER` | `false` | 是否启动 Web 服务器 |

### Git 推送配置

| 环境变量 | 默认值 | 说明 |
|---------|-------|------|
| `GIT_AUTO_PUSH` | `false` | 是否启用自动推送 |
| `GIT_USER_NAME` | - | Git 用户名 |
| `GIT_USER_EMAIL` | - | Git 邮箱 |
| `GIT_COMMIT_PREFIX` | `TrendRadar Update` | 提交信息前缀 |

### 话题分析配置

| 环境变量 | 默认值 | 说明 |
|---------|-------|------|
| `CURSOR_KEY` | - | Cursor API Key（必需） |

## Docker Compose 示例

```yaml
version: '3.8'
services:
  trendradar:
    image: trendradar:latest
    environment:
      - RUN_MODE=cron
      - CRON_SCHEDULE=*/30 * * * *
      - IMMEDIATE_RUN=true
      - GIT_AUTO_PUSH=true
      - GIT_USER_NAME=your-name
      - GIT_USER_EMAIL=your-email@example.com
      - CURSOR_KEY=your_cursor_api_key
    volumes:
      - ./config:/app/config:ro
      - ./output:/app/output
      - ~/.ssh:/root/.ssh:ro  # 用于 Git SSH 认证
      - ./.git:/app/.git      # 用于 Git 操作
```

## 常见问题

### Q: 话题分析没有执行？

检查以下几点：
1. `CURSOR_KEY` 环境变量是否正确设置
2. `tools/run_topic_analysis.sh` 脚本是否存在
3. 查看容器日志确认是否有错误信息

### Q: Git 推送失败？

检查以下几点：
1. `.git` 目录是否正确挂载到容器
2. SSH 密钥是否正确挂载到 `/root/.ssh`
3. `GIT_USER_NAME` 和 `GIT_USER_EMAIL` 是否配置

### Q: 定时任务不执行？

检查以下几点：
1. `RUN_MODE` 是否设置为 `cron`
2. `CRON_SCHEDULE` 表达式是否正确
3. 使用 `docker logs` 查看 supercronic 的输出

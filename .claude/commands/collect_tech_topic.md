# 收集互联网/科技行业热点话题

---

## 任务

从多平台收集当前正在发酵的互联网/科技热点，输出结构化「候选热点清单」（含可追溯链接池）。

---

## Steps（步骤）

### 步骤 1：精确确定时间范围

**1. 锚定当前时间**
- **必须**首先确认当前的 **系统日期** (Current Date)。
- 所有“近 X 天”的计算均以此日期为**终点**倒推。

**2. 设定搜索窗口**
- **默认策略**（智能回溯）：
  - **第一轮**：搜索 **近 3 天** 内的新闻/话题。
  - **第二轮**：若第一轮有效话题 **< 10 个**，将起点扩展至 **近 5 天**。
  - **第三轮**：若第二轮仍 **< 10 个**，最远扩展至 **近 7 天**。
  - **强制终止**：任何情况下，不搜索超过 **7 天前** 的内容。

- **指定策略**（用户指定参数）：
  - 严格锁定在用户要求的 `时间范围` 内。
  - 严禁自动扩展或缩减。

**3. 时间有效性校验（关键）**
- **发布时间检查**：内容的发布时间必须在窗口内。
- **事件发生时间检查**：**核心事件**必须发生在窗口内。
  - *拒绝*：旧闻重发、历史回顾、非当下的盘点。
  - *例外*：旧事件在窗口内有**重大实质性新进展**（如：判决结果公布、新功能正式上线）。

### 步骤 2：确认收集范围与筛选规则

**地域/语种**
- 默认中文互联网 + 海外主流科技媒体

**话题边界定义**
✅ 采纳范围
- 互联网产品/平台（大厂/独角兽/出海）
- 消费电子
- 科技与社会交叉议题（如：外卖算法与劳动者权益、网约车安全、大数据杀熟、网络暴力与治理、青少年防沉迷、数字遗产、AI换脸诈骗等具有广泛社会影响力的科技事件）
- 智能车的"软件与算力"部分
- AI/大模型/Agent/机器人
- 芯片/算力/半导体
- 云/数据中心
- 操作系统/开发者生态
- 网络安全
- 开源社区/开源项目
- SaaS/企业服务
- 监管与反垄断（与平台/数据/AI 强相关）

❌ 排除范围
- 纯娱乐明星八卦
- 与科技无关的纯社会新闻
- 与科技无关的泛财经
- 缺少可信来源的阴谋论
- 明显的营销软文或通稿
- 过于边缘的小众技术讨论（除非重大突破）
- 政治敏感话题

**重点覆盖领域**
- 人工智能（AI/大模型/Agent/机器人等）
- 大厂动态（Google、Apple、Microsoft、Amazon、NVIDIA、Tesla、OpenAI、Meta、Anthropic、阿里巴巴、字节、腾讯、百度、小红书、BiliBili、华为等）
- 新产品发布与更新
- 行业重大收购/融资/上市
- 技术突破与开源项目
- 科技政策与监管
- 创业公司/独角兽动态

**信息源优先级**
- 官方新闻稿 > 科技媒体 > 社交媒体讨论

### 步骤 3：多平台抓取候选话题

**要求覆盖至少 3 类信号源**

| 类别 | 用途 | 平台示例 |
|------|------|----------|
| **热榜/趋势类** | 发现"当下热" | 🇨🇳 微博热搜、知乎热榜、BiliBili热榜<br>🌍 Google Trends、Hacker News、Reddit（r/technology / r/MachineLearning）、Product Hunt |
| **科技媒体/行业媒体** | 确认"行业相关 + 信息密度高" | 🇨🇳 36氪、虎嗅、IT之家、少数派、量子位、机器之心、晚点<br>🌍 The Verge、Ars Technica、TechCrunch、Wired |
| **官方/权威源** | 提高可信度 | 公司官网公告/博客、监管机构公告、开源项目 Release Notes、主流安全厂商通告、GitHub/Apache/基金会公告 |

**抓取要求**
- **使用 `trend-radar` MCP 工具**采集候选话题，调用方式：
  - `aggregate_news`（limit=30, include_url=false）— 跨平台新闻聚合去重，一次调用完成候选抓取、热度采集与跨平台合并
- **不要读取本地 output 目录下的文件**，所有数据均通过 MCP 接口实时获取
- 当通过 `trend-radar` MCP 工具采集的候选条目数量不足 10 条时，再使用 **WebSearch 做兜底**补充

### 步骤 4：话题归一化与聚类去重

**目标**
- 把"同一事件/同一发布/同一事故"在不同平台的不同说法合并为一个话题

**去重方式**
- 直接使用 `aggregate_news` 返回的聚合结果（无需额外调用）：
  - `is_cross_platform=true` 的条目已完成跨平台合并，直接保留
  - `platform_count` 越高覆盖面越广，优先保留
- 标题相似 + 主体相同 + 时间接近 → **手动合并**，保留信息最完整的一篇为主链接

### 步骤 5：筛选与评估

**筛选目标**
- 从候选池中选出 **5-10 个** 最有价值的热点话题

**两阶段筛选**

**第一阶段（零额外 MCP 调用）**：直接基于 `aggregate_news` 返回的数据打分：
- 🔥 热度：`aggregate_weight`（权重越高=热度越高）+ `platform_count`（覆盖平台数）
- ⏰ 时效性：话题发布时间距今（越近越高）
- 📊 深度潜力：LLM 对话题内容的常识判断
- 💬 争议性：LLM 对话题性质的常识判断（涉及利益冲突/技术争论/社会影响的话题争议性更高）

**第二阶段（仅对初筛 Top 8 调用）**：
- `analyze_topic_trend(topic=关键词, analysis_type="viral")` — 确认是否有异常热度飙升，修正热度/时效性评分

**评估维度**（每项 1-5 分）

| 维度 | 评分标准 |
|------|----------|
| 🔥 热度 | 5=多平台覆盖且 aggregate_weight 排名前5 / viral 检测到异常飙升；1=仅个别讨论 |
| ⏰ 时效性 | 5=24小时内 / viral 上升趋势；1=超过一周 |
| 📊 深度潜力 | 5=有多角度延展空间；1=单一事实 |
| 💬 争议性 | 5=观点对立明显；1=共识性新闻 |

**排序规则**
- 按综合评分排序，保留得分最高的 **10 个话题**

### 步骤 6：话题信息整理

对每个入选话题，整理以下结构化信息：

| 字段 | 要求 |
|------|------|
| 话题名称 | 简洁明了，一眼可知 |
| 话题类型 | 产品发布/公司动态/技术突破/行业趋势/争议事件/融资上市/政策监管/科技社会议题 |
| 一句话描述 | ≤50字，概括核心信息 |
| 关键词标签 | 3-5个，便于归档检索 |
| 热度来源 | 哪些平台/媒体在讨论 |
| 推荐切入角度 | 1-2个内容创作方向 |
| 评估得分 | 步骤5的评分结果 |

**链接获取**：对每个入选话题调用 `search_news(query=话题关键词, include_url=true, limit=3)` 获取主链接和补充链接。

## Context（上下文）

### 输入参数

| 参数 | 必选 | 默认值 | 说明 |
|------|------|--------|------|
| `区域` | 否 | 全球 | 可选值："国内"/"海外"/"全球" |
| `时间范围` | 否 | 自动（见步骤1） | 可选值："今日"/"近24小时"/"近三天"/"近一周"/"近一月"；若不指定则按步骤1的自动扩展逻辑执行 |
| `细分领域` | 否 | 全部 | 可指定："AI"/"大厂"/"创业"/"开源"/"硬件"等 |

### 业务背景
- 本任务是内容生产流水线的**第一环**
- 输出结果将传递给 `event_pipeline` 进行深度素材搜索与内容创作
- 因此需要确保话题的**可延展性**和**链接可追溯性**

## 备注
- ✅ 输出内容使用**中文**
- ✅ 确保来源的**多样性**，不要只依赖单一渠道
- ✅ 若结果偏少：
  - 扩展时间窗口到 **最近 7 天**，最多只能 7 天
  - 放宽区域限制到 **全球**
- ✅ 优先选择有**深度挖掘价值**的话题
- ✅ 每个话题必须有**可追溯的链接**
